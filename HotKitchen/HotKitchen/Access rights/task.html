Description

With a complete user registration, authentication, and profile system in place, it's time to build the core functionality of our HotKitchen application: the menu. This involves creating, managing, and displaying meals and their categories.

In this stage, you will introduce role-based access control. While any authenticated user can view the menu, only users with a staff user type will have the permission to add new meals and categories. This is a common pattern in applications where certain actions are restricted to administrators or privileged users.

This project was recently updated. If you started before the updates and are facing issues, check the end of the Stage 1 description for notes on the update.

Objectives

Your goal is to define the data structures for meals and categories and implement API endpoints to manage them, enforcing the new access rules.

  • Create Data Models:

    • Define a Meal data class to store meal information.

    • Define a Category data class to store category information.

  • Implement API Endpoints:

    • POST /meals and POST /categories: Restricted endpoints for staff users to add new items.

    • GET /meals and GET /categories: Publicly accessible endpoints for any authenticated user to view menu items. These will support fetching all items or a single item by its ID.

Data Models

You will need to create the following data structures, which will be used for both database storage and API responses.

Meal

  • mealId (integer) - The unique identifier for the meal.

  • title (string) - The name of the meal.

  • price (float) - The price of the meal.

  • imageUrl (string) - A URL to an image of the meal.

  • categoryIds (list of integers) - A list of category IDs this meal belongs to.

Category

  • categoryId (integer) - The unique identifier for the category.

  • title (string) - The name of the category.

  • description (string) - A detailed description of the category.

API Endpoint Specifications

All endpoints below require a valid Bearer token for authentication.

POST /meals:

Adds a new meal to the database.

  • Access Control: staff users only.

  • Successful Response (200 OK): Returns the newly created meal object.

  • Failure (Access Denied) (403 Forbidden): Occurs if a non-staff user attempts this action.

    {
    "status": "Access denied"
}

  • Failure (400 Bad Request): Occurs if addition failed.

POST /categories:

Adds a new category to the database.

  • Access Control: staff users only.

  • Successful Response (200 OK): Returns the newly created category object.

  • Failure (Access Denied) (403 Forbidden): Occurs if a non-staff user attempts this action.

    {
    "status": "Access denied"
}

  • Failure (400 Bad Request): Occurs if addition failed.

GET /meals:

Retrieves a list of all meals.

  • Access Control: All authenticated users.

  • Successful Response (200 OK): Returns a JSON array of all meal objects.

GET /meals?id={id}:

Retrieves a single meal by its unique ID.

  • Access Control: All authenticated users.

  • Successful Response (200 OK): Returns the JSON object for the requested meal.

  • Failure (Not Found) (400 Bad Request): Occurs if no meal with the specified ID exists.

GET /categories:

Retrieves a list of all categories.

  • Access Control: All authenticated users.

  • Successful Response (200 OK): Returns a JSON array of all category objects.

GET /categories?id={id}:

Retrieves a single category by its unique ID.

  • Access Control: All authenticated users.

  • Successful Response (200 OK): Returns the JSON object for the requested category.

  • Failure (Not Found) (400 Bad Request): Occurs if no category with the specified ID exists.

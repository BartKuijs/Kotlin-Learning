Description

Every modern application requires user management capabilities. Registration and authorization are core components that identify users, tailor their experiences, and securely keep their data. We will build these basic functions for our application in this stage.

In the first stage, you need to implement the registration and authorization system. You should be able to register a new user and later sign them in with the same credentials. Store all user data in a database to maintain the information after server restarts.

This project was recently updated to use Ktor 3.3.x. If you’re returning after some time, please refer to the end of the description and Ktor’s documentation for migration guides.

Objectives

  • Create and run a Ktor application that listens on port 28852.

  • Run a database of your choice and configure your application to connect to it.

    This project includes a dependency for PostgreSQL. If you plan to use a different database, add the appropriate dependencies.

  • Implement the following API endpoints:

POST /signup:

Handles new user registration.

  • Request Body: A JSON object containing email, userType, and password.

  • Successful Response (200 OK):

    {
    "status": "Signed Up"
}

  • Failure Response (403 Forbidden): This occurs if a user with the given email already exists.

    {
    "status": "Registration failed"
}

Allowing users to set their own userType (like "staff" or "admin") is done here for educational purposes only. In a real-world application, roles should be assigned by an administrator to prevent security vulnerabilities.

POST /signin:

Handles user authorization.

  • Request Body: A JSON object containing email and password.

  • Successful Response (200 OK):

    {
    "status": "Signed In"
}

  • Failure Response (403 Forbidden): This occurs if the email is not found or the password does not match.

    {
    "status": "Authorization failed"
}
Examples

Example 1:

  1. First POST request for /signup:

    Request body:

    {
    "email": "example@domain.name",
    "userType": "staff",
    "password": "awesomepass123"
}

    Response (200 OK):

    {
    "status": "Signed Up"
}

  2. One more POST request for /signup with the same email:

    Request body:

    {
    "email": "example@domain.name",
    "userType": "staff",
    "password": "awesomepass123"
}

    Response (403 Forbidden):

    {
    "status": "Registration failed"
}

    Registration failed because the user with this email is already registered.

Example 2:

A POST request for /signin with the wrong email and password:

Request body:

{
    "email": "example@domain.name",
    "password": "wrongpass"
}

Response (403 Forbidden):

{
    "status": "Authorization failed"
}

Example 3:

A POST request for /signin:

Request body:

{
    "email": "example@domain.name",
    "password": "awesomepass123"
}

Response (200 OK):

{
    "status": "Signed In"
}

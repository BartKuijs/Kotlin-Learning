Description

In the previous stage, you built a basic registration and sign-in system. However, requiring a user to send their email and password with every request is inefficient and insecure. A much better industry-standard approach is to use tokens. A user authenticates once with their credentials, receives a temporary token, and then uses that token to access protected resources.

In this stage, you will upgrade your authentication system to use JWTs. You will also implement server-side validation for email and password formats and provide more specific error messages to the user.

This project was recently updated. If you started before the updates and are facing issues, check the end of the Stage 1 description for notes on the update.

Objectives

Your goal is to refactor the authentication logic to incorporate JWTs, add input validation, and introduce a new endpoint for token verification.

  • Implement Input Validation:

    Before processing any registration, you must validate the user's email and password against the following rules:

    • Valid Email: Must consist of a prefix and a domain (e.g. example@mail.com).

    • Valid Password: Must be at least six characters long and contain both letters and numbers.

  • Update Existing API Endpoints:

    The /signup and /signin endpoints will now return a JWT upon success instead of a simple status message.

  • Create a New API Endpoint:

    You will add a GET /validate endpoint to check the validity of a JWT.

API Endpoint Specifications

POST /signup:

This now handles input validation and returns a JWT upon successful registration.

  • Successful Response (200 OK):

    {
    "token": "<JWT token>"
}

  • Failure: Invalid Email (403 Forbidden):

    {
    "status": "Invalid email"
}

  • Failure: Invalid Password (403 Forbidden):

    {
    "status": "Invalid password"
}

  • Failure: User Already Exists (403 Forbidden):

    {
    "status": "User already exists"
}

POST /signin:

This now returns a JWT upon successful authorization.

  • Successful Response (200 OK):

    {
    "token": "<JWT token>"
}

  • Failure: Invalid Credentials (403 Forbidden):

    {
    "status": "Invalid email or password"
}

GET /validate:

This new, protected endpoint verifies a Bearer token sent in the Authorization header.

  • Request Header:

    Authorization: Bearer <JWT token>

  • Successful Response (200 OK): The response body is plain text.

    Hello, <userType> <email>

    Where <userType> and <email> are of the user whose token was received.

  • Failure Response (401 Unauthorized): This is returning if the token is missing, malformed, or invalid. No response body is required.

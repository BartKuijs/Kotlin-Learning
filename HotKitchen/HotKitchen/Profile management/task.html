Description

You have successfully implemented a robust token-based authentication system. A user can now register and sign in to receive a JWT, proving their identity. The next step is to build a full-fledged user profile where they can store and manage personal information like their name, phone number, and address.

This is where we'll introduce an important concept: the separation of authentication data (credentials like email and password hash) from profile data (personal information). When a user signs up, only their authentication data is created. Their detailed profile is initially empty and can be created or updated later.

In this stage, you will implement the logic for creating, viewing, updating, and deleting a user's profile. All these actions will be protected and will operate on the account associated with the provided JWT.

This project was recently updated. If you started before the updates and are facing issues, check the end of the Stage 1 description for notes on the update.

Objectives

Your goal is to create a user profile system by implementing three new API endpoints. All endpoints must be protected and require a valid Bearer token for authorization.

  • GET /me: Fetches the complete profile information for the authenticated user.

  • PUT /me: Creates or updates the user's profile information.

  • DELETE /me: Deletes the user's entire account, including both their profile and their credentials.

API Endpoint Specifications

GET /me:

Fetches the detailed profile information for the currently authenticated user.

  • Successful Response (200 OK): Returns the user's profile data.

    {
    "name": "Goose",
    "userType": "client",
    "phone": "+79999999999",
    "email": "example@gmail.com",
    "address": "address"
}

  • Failure Response (400 Bad Request): This occurs if the user is authenticated but has not created their profile information yet.

PUT /me:

Creates or updates the profile information for the authenticated user. This method performs an "upsert" operation: if the profile doesn't exist, it's created; if it already exists, it's updated with the new data.

  • Request Body: A JSON object with the user's full profile.

  • Important Constraint: The email field in the request body must match the email associated with the JWT. You should not change the email.

  • Successful Response (200 OK): Returns the newly created or updated profile data.

    {
    "name":"newName",
    "userType":"newType",
    "phone":"+79999999999",
    "email":"example@gmail.com",
    "address":"newAddress"
}

  • Failure Response (400 Bad Request): This occurs if the email in the request body does not match the email in the authentication token.

DELETE /me:

Permanently deletes the authenticated user's account. This action is irreversible and removes all information associated with the user, including both their profile and their authentication credentials.

  • Successful Response (200 OK): Indicates that the user account was successfully deleted. No response body is required.

  • Failure Response (404 Not Found): This occurs if the user account does not exist (for example, if you try to delete the same user twice).
